Integrando o trabalho: fast-forward e merge de três vias

A feature ficou pronta

V Você feature/login
+adiciona login +valida senha 2 commits novos
M main main
Nenhum commit novo desde que a branch nasceu.

Hora de trazer o trabalho de volta. Merge é isso: a main recebe o que a branch fez.

projeto-rpa
$ 
Switched to branch 'main'
$ 
Updating a1b2c3d..9f8e7d6
Fast-forward
 login.php | 2 ++

A main não andou: o merge é só o ponteiro avançando.
Nenhum commit novo é criado.

Dois jeitos de integrar

Fast-forward a main só alcança a feature
Três vias as duas andaram: nasce um commit de merge, com dois pais

Três coisas para lembrar

1

Faça o merge estando na branch que recebe. git switch main primeiro, git merge feature/login depois.

2

Partes diferentes do código se combinam sozinhas. Quando os dois lados mexem na mesma linha, é conflito: o próximo módulo.

3

--no-ff é opção, não regra. Força um commit de merge para a feature ficar visível como uma "bolha" no histórico. Use só quando isso tiver valor.

Trabalho integrado. Histórico linear.

Fast-forward quando dá.
Commit de merge quando precisa.
