As três áreas do Git: de onde vem cada comando

Primeiro dia na Iron Systems

projeto-rpa/
index.php
config.php
nenhum histórico. nenhuma memória.
Quem mudou a porta do banco ontem?
Qual versão estava funcionando na semana passada?
Ninguém sabe. A pasta não lembra de nada.

Sua primeira tarefa: colocar o projeto sob controle de versão.

projeto-rpa
$ 
Initialized empty Git repository in projeto-rpa/.git/

A pasta virou um repositório.
Cada mudança agora pode virar história.

As três áreas

working dir
index.php
README.md
git add
staging
README.md
git commit
repositório
projeto-rpa — main
$

Na dúvida, git status

projeto-rpa — main
$ git status
On branch mainChanges to be committed:
  new file:   contato.phpChanges not staged for commit:
  modified:   README.md
1

Ele diz em que área cada arquivo está. Verde: na bandeja. Vermelho: ainda só no disco.

2

Um commit, uma intenção. Duas mudanças sem relação viram dois commits: git add aceita o nome do arquivo.

Repositório criado. Primeiro commit feito.

Tudo no Git passa por três áreas.
Agora é com você.
