O fluxo oficial da Iron Systems: commits pequenos, direto na main, várias vezes por dia

Alguém chegou antes

projeto-rpa — main
$ 
[main 3e4f5a6] adiciona página sobre
$ 
 ! [rejected]        main -> main (fetch first)
hint: Updates were rejected because the remote contains work you do not have.
A
Ana fez pushAna acabou de enviar “ajusta título do index” para origin/main

O remoto só aceita push quando o que ele tem é ancestral do seu commit. A Ana passou na frente.

projeto-rpa — main
$ 
Successfully rebased and updated refs/heads/main.
$ 
To github.com:rpa-exemplo/projeto-rpa.git
   a1b2c3d..7d8e9f0  main -> main

Seus commits reaplicados por cima dos da Ana.
Histórico linear, sem commit de merge.

Uma linha só, o time inteiro

commit pequenocompila, não quebra
→
git pull --rebasetraz o que chegou
→
git pushenvia já
… várias vezes por dia

Quanto mais tempo um commit fica só na sua máquina, maior a chance de conflito. Pequeno e frequente vence grande e raro.

Proibido na main

git push --force
git reset
O motivo: a main está na máquina de todo mundo. Reescrever o histórico do remoto deixa os repositórios dos colegas divergentes, o próximo pull vira conflito e trabalho pode se perder.
git revert <commit>

desfaz com um commit novo. Nada é apagado; tudo fica auditável.

Push aceito. Histórico linear.

Commit pequeno, pull --rebase, push.
Várias vezes por dia. Agora é com você.
